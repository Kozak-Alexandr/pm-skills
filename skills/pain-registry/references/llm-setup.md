# Настройка модели для интерфейса

Интерфейсу нужна своя модель: Claude Code он вызвать не может. Без модели всё работает на эвристике по ключевым словам, но она находит меньше половины болей и плохо раскладывает их по категориям.

1. Проверь `~/.llm.env`: заполнены ли `LLM_BASE_URL`, `LLM_MODEL` и есть ли непустой `LLM_API_KEY` (значение не выводи: `grep -c "^LLM_API_KEY=." ~/.llm.env`).
2. Если нет, спроси, можно ли отправлять тексты встреч во внешний сервис, и предложи варианты:

| Вариант | Значения в `~/.llm.env` | Когда |
|---|---|---|
| Облачный API | OpenAI: `https://api.openai.com/v1`, `gpt-4.1-mini`; OpenRouter: `https://openrouter.ai/api/v1`, модель из каталога | есть ключ, внешние сервисы разрешены |
| Корпоративный шлюз | адрес и модель от своих админов | внешние сервисы запрещены |
| Ollama на своём компьютере | `http://localhost:11434/v1`, ключ `ollama`, модель например `qwen2.5:14b` | данные не должны покидать компьютер |

Если тексты наружу нельзя, а своего шлюза и видеокарты нет, вернись к способу 1 из SKILL.md только с разрешения пользователя, иначе работай на эвристике.

3. Адрес и модель впиши сам. Ключ пусть вставит пользователь: открой файл (`notepad %USERPROFILE%\.llm.env` на Windows, `open -e ~/.llm.env` на macOS). Ключ в чат не проси; если пользователь всё же прислал его, запиши в файл и посоветуй перевыпустить.
4. Если интерфейс уже запускался, удали `~/pain-registry/config.json` или поправь его на вкладке «Настройки»: конфиг создаётся при первом запуске.
5. Корпоративный шлюз за прокси: на вкладке «Настройки» выключи использование системного прокси (`use_system_proxy`), при ошибке сертификата укажи `ca_bundle`.

Проверка: на вкладке «Настройки» в интерфейсе видно, задан ли ключ, а в левом нижнем углу - подключённая модель.
