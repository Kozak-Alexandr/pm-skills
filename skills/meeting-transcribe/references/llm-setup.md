# Настройка LLM при первом запуске

LLM нужна для двух шагов: свести две версии распознавания в чистый текст и написать саммари. Распознавание речи от неё не зависит.

## Как провести пользователя

1. Проверь `~/.llm.env`: заполнены ли `LLM_BASE_URL` и `LLM_MODEL`, есть ли строка `LLM_API_KEY=` с непустым значением. Значение ключа не выводи: `grep -c "^LLM_API_KEY=." ~/.llm.env`.
2. Если ничего не настроено, коротко объясни варианты и спроси, какой подходит. Главный вопрос: можно ли отправлять текст встреч во внешний сервис.

| Вариант | Что нужно | Когда выбирать |
|---|---|---|
| Claude Code (по умолчанию) | ничего, если `claude` уже залогинен | быстрее всего начать; текст уходит в Anthropic |
| Облачный API | адрес, ключ, модель | есть ключ OpenAI, OpenRouter или другого OpenAI-совместимого сервиса |
| Корпоративный шлюз | адрес, ключ, модель от своих админов | компания запрещает внешние сервисы, но держит свой шлюз |
| Локальная модель | установленная Ollama и скачанная модель | текст не должен покидать компьютер; нужна видеокарта от 12 ГБ, иначе саммари будет заметно слабее |

Примеры значений:

- OpenAI: `LLM_BASE_URL=https://api.openai.com/v1`, `LLM_MODEL=gpt-4.1-mini` (дешевле) или `gpt-4.1`.
- OpenRouter: `LLM_BASE_URL=https://openrouter.ai/api/v1`, модель из каталога, например `qwen/qwen3-235b-a22b` или `anthropic/claude-sonnet-4.5`.
- Ollama: `LLM_BASE_URL=http://localhost:11434/v1`, `LLM_API_KEY=ollama` (любая строка, Ollama ключ не проверяет), `LLM_MODEL=qwen2.5:14b` или другая скачанная модель (`ollama pull qwen2.5:14b`). Этот вариант подходит обоим скиллам. Длинные встречи не влезут в контекст по умолчанию: попроси запускать Ollama с `OLLAMA_CONTEXT_LENGTH=32768`.

3. Адрес и модель не секрет: впиши их в `~/.llm.env` сам. Ключ пусть пользователь вставит сам: открой файл (`notepad %USERPROFILE%\.llm.env` на Windows, `open -e ~/.llm.env` на macOS) и попроси вставить ключ после `LLM_API_KEY=` и сохранить. Ключ в чат не проси. Если пользователь всё же прислал его в чат, запиши в файл и посоветуй перевыпустить ключ: он остался в истории переписки.
4. Проверь подключение: `~/.venvs/transcribe/Scripts/python.exe <скилл>/scripts/check_llm.py`. Скрипт делает короткий запрос и пишет `OK` или текст ошибки, ключ не печатает.

Типичные ошибки проверки:
- `401` или `invalid api key`: ключ не тот или вставлен с пробелом;
- `404` или `model not found`: опечатка в имени модели;
- `CERTIFICATE_VERIFY_FAILED` у корпоративного шлюза: нужен `LLM_CA_BUNDLE` с путём к корневому сертификату;
- долгое зависание у корпоративного шлюза: прокси не пускает к внутреннему хосту, добавь `LLM_NO_PROXY=1`;
- `claude CLI не залогинен`: запусти `claude` в терминале и выполни `/login`.

## Токен Hugging Face для разделения спикеров

Без него расшифровка работает, но вся встреча будет одним спикером. Проведи по шагам:

1. Войти или зарегистрироваться на https://huggingface.co (бесплатно).
2. Открыть https://huggingface.co/pyannote/speaker-diarization-community-1, заполнить короткую форму и нажать «Agree and access repository».
3. Создать токен типа Read на https://huggingface.co/settings/tokens.
4. Открой `~/meeting-transcribe/.env` и попроси вставить токен после `HF_TOKEN=`. Проверь наличие без вывода: `grep -c "^HF_TOKEN=hf_" ~/meeting-transcribe/.env`.
