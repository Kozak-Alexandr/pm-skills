# Расшифровка встреч

Конвейер: звук → кто когда говорит (pyannote) → две модели распознавания на каждый фрагмент (GigaAM v3 лучше всех пишет русскую речь, Whisper large-v3 лучше пишет английские термины и числа) → LLM сводит две версии по словарю продукта → саммари, задачи, отчёт.

Код лежит в `scripts/` этого скилла, данные пользователя отдельно, в `~/meeting-transcribe` (или `$TRANSCRIBE_HOME`): `out/` с результатами, `glossary.md` со словарём, `kb/` с базой людей и задач, `.env` с токеном Hugging Face. Настройки LLM в `~/.llm.env`.

## Перед первым запуском

Проверь, что окружение есть: `~/.venvs/transcribe/Scripts/python.exe` на Windows. Если нет, предложи установку и предупреди, что она долгая (torch 2,5 ГБ и модель Whisper 3 ГБ, обычно 20-60 минут):

```
powershell -ExecutionPolicy Bypass -File <скилл>/scripts/setup.ps1
```

Запускай её в фоне. Ключи и токены пользователь вписывает сам; в чат их не проси и не выводи в терминал (проверяй только наличие, например `grep -q "^HF_TOKEN=hf_" ~/meeting-transcribe/.env`):

- `HF_TOKEN` в `~/meeting-transcribe/.env` нужен для разделения на спикеров, без него вся встреча станет одним «Спикером 1». Токен read-типа с https://huggingface.co/settings/tokens, плюс один раз принять условия на https://huggingface.co/pyannote/speaker-diarization-community-1.
- LLM для сведения текста и саммари: OpenAI-совместимый API в `~/.llm.env` (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`). Если не заполнено, используется Claude Code CLI (`claude -p`), он должен быть залогинен.

## Запуск

Если спикеры важны (почти всегда да), а токена нет, сначала скажи об этом и дай инструкцию выше: перезапуск с диаризацией потом всё равно пересчитает распознавание. Спроси число участников, если его легко назвать: `--speakers N` заметно улучшает разделение.

```
~/.venvs/transcribe/Scripts/python.exe <скилл>/scripts/transcribe.py "<путь к записи>" [опции]
```

| Опция | Когда |
|---|---|
| `--speakers N` | известно точное число участников |
| `--custdev` | интервью с клиентом: профиль компании, боли, ожидания, сигналы для продукта |
| `--context "..."` | что известно о встрече: клиент, участники, продукты, как их коверкает распознавание; можно путь к .txt/.md |
| `--llm api` | OpenAI-совместимый API из `~/.llm.env`; по умолчанию, если он заполнен |
| `--llm claude` | Claude Code CLI; по умолчанию, если API не настроен |
| `--llm local` | локальный сервер без ключа, например Ollama (`LOCAL_LLM_URL`, `LOCAL_LLM_MODEL`) |
| `--asr-only` | только стенограмма, без LLM |
| `--no-diar` | без разделения на спикеров |

Распознавание всегда локальное, но на этапах сведения и саммари текст встречи уходит выбранной LLM. Если встреча конфиденциальная, а LLM внешняя, спроси пользователя, можно ли так; иначе `--llm local` или `--asr-only`.

На вход можно дать и готовую текстовую расшифровку (.txt из Zoom, Teams, Телемоста): тогда распознавание пропускается.

Запускай в фоне и следи за логом: на видеокарте NVIDIA час записи идёт 30-40 минут, на CPU в разы дольше. Этапы печатаются строками `[ N с] этап`. Если остановить процесс во время «подготовки звука», удали недописанные `audio.wav` и `audio.m4a` в папке встречи, иначе следующий запуск возьмёт обрезанный звук. Остальные этапы кэшируются, и повторный запуск продолжает с места остановки; смена `--llm` не перезапускает распознавание.

## Что отдать пользователю

Результат в `~/meeting-transcribe/out/<дата>_<имя файла>/`:

- `report.html`: участники, полоса «кто когда говорил», темы на шкале времени, решения, вопросы, задачи, стенограмма с поиском, плеер (клик по таймкоду включает запись с этого места);
- `report.pdf`: тот же отчёт в PDF;
- `summary.md`, `transcript.md`: то же текстом.

Пришли отчёт и PDF файлами и коротко перескажи встречу: о чём, решения, задачи с исполнителями и сроками, открытые вопросы. Пиши по сути, без воды.

## После прогона

- Конвейер добавляет людей, команды и задачи встречи в базу `~/meeting-transcribe/kb` и пересобирает карту `kb/mindmap.html`. Если встреча личная или не рабочая, спроси, оставить ли её в базе (удалить: файл встречи в `kb/meetings/`, затем `scripts/kb.py`).
- Новые термины копятся в `kb/glossary-candidates.md`. Предложи отметить нужные `[x]` и запустить `scripts/update_glossary.py`; можно добрать термины из материалов продукта: `update_glossary.py --scan <папка с .md>`.
- При первом запуске `~/meeting-transcribe/glossary.md` почти пустой. Если пользователь ещё не заполнял его, предложи вместе описать продукт, команду и жаргон: это главный рычаг точности.

Если что-то падает или идёт медленно, смотри `references/troubleshooting.md`.
